# 儿童版中国哲学史创作计划

## 1. 核心目标
### 目标概述
创作一本面向8-12岁读者的《儿童版中国哲学史》，让孩子像探险家一样在中国哲学的原野上发现问题、遇见智者、生成自己的思考。核心不是灌输概念，而是通过故事化、互动化的方式，激发儿童对哲学问题的天然好奇心。

### 背景与动机
- **教育价值**：填补市场上真正尊重儿童智力、不简化哲学深度的童书空白
- **文化传承**：以冯友兰“释古”精神为基础，让孩子同情理解古人“为什么这样想”
- **跨学科融合**：结合中国哲学史、儿童心理学、互动教学设计，打造可读可用的思想探险手册
- **验证标准**：所有内容必须通过“8-12岁理解度测试”，确保语言、比喻、互动设计真正适配目标读者

## 2. 要求与标准
- **产出要求**：
  - **书稿评估与优化**：基于用户上传的完整书稿《和古人一起想问题——中国哲学探险手册（完整版）.md》，进行全面评估，确保符合儿童化、探险家视角、互动设计等要求；重点优化王阳明章节的独立性与完整性；调整语言比喻，强化8-12岁认知锚点；以原书12章目录为结构基准，确保全书章节划分与顺序一致。
  - **插图与图表设计**：为全书12章设计配套插画、图表、视觉元素，每章提供清晰的视觉描述与位置指引；建立插图素材库（`data/illustration_references/`），确保视觉风格统一。
  - **阶段性HTML样张**：每章首先生成HTML格式样张，确保图文并茂，样式统一，便于审阅和迭代。
  - **最终交付物**：一本图文并茂的电子书（HTML格式优先，PDF格式可选），包含优化后的全书文字内容、专业插画/图表设计、精美排版，确保视觉吸引力与哲学深度完美结合。
  - **验收标准**：
    - 每章必须包含“思想剧场”（校园/家庭小故事引出问题）、“想一想”互动框（激发孩子立场选择与共情）、“古人说”（经典原文带拼音、解释、趣味图）、“智慧探险地图”（该章核心问题、代表人物、思想工具）
    - 语言必须使用儿童能懂的比喻（如“道=游戏底层代码”“仁=心里那个‘不想让别人难过’的开关”）
    - 保持幽默感与智力尊重（如庄子是“爱讲怪故事的反讽大叔”，韩非子是“冷静理性的游戏规则设计师”）
    - 在合适处加入“全球望远镜”栏目，用一两句话对比同时期古希腊或其他文明的思考
    - 所有历史人物和思想需符合基本史实，不戏说，表达生动
    - **图文并茂要求**：每章需为插画/图表提供明确的视觉描述与位置指引，确保后续视觉设计能准确传达哲学概念；最终成书需包含封面、目录、章节页、插图等完整书籍元素
    - **目录完整性**：目录页必须使用原始书稿中的完整标题格式，包括括号内的哲学家信息（如“第一章：世界是从哪儿来的？（老子、孔子、神话）”），确保与用户最初上传的目录完全一致

- **风格偏好**：
  - **整体调性**：亲切、好奇、开放，像一位懂得孩子心理的智者朋友在引导探险
  - **语言风格**：活泼不失深度，幽默不失严谨，比喻具体形象，避免抽象术语堆砌
  - **视觉想象**：文字需有强烈的画面感，为后续可能的插画、漫画提供清晰的方向

- **文件目录规则**：
  - **核心交付资产**：`outputs/儿童哲学史/{章节名称}/{文档名称}`
  - **过程资料与调研**：`temp/儿童哲学史/{章节名称}/`
  - **共享状态库**：`data/shared_state/state.db`（用于记录创作进度、术语映射、案例库）

- **数据依赖**：
  - **外部信源**：需联网搜索中国哲学史资料、儿童教育心理学研究、现有童书改编案例、中西哲学对比资料
  - **技能参考**：借鉴`personalized-learning-init`中的学习目标拆解与互动设计方法

- **通知规则**：
  - **评估报告提醒**：完整书稿评估完成后立即通知用户审阅评估结果
  - **优化进度同步**：每完成3章优化后通知用户查看进展
  - **插图设计里程碑**：每完成5章插图设计后通知用户审阅视觉风格

## 4. 共享状态库契约

```sql
-- 记录章节创作进度
CREATE TABLE IF NOT EXISTS chapter_progress (
  chapter_title TEXT PRIMARY KEY,
  status TEXT NOT NULL, -- 'pending', 'in_progress', 'completed'
  completed_at TEXT,
  word_count INTEGER,
  feedback_summary TEXT
);

-- 记录核心术语的儿童化映射
CREATE TABLE IF NOT EXISTS philosophy_terminology_mapping (
  adult_term TEXT PRIMARY KEY,

```
- **去重口径**：按`chapter_title`唯一标识章节进度，避免重复创作
- **幂等写入**：使用`INSERT OR IGNORE`保证重复执行不产生重复记录

## 5. 技术经验沉淀
### 排版流程技术难点与解决方案（基于第一章样张验证）
**已验证技术路径**：pandoc + wkhtmltopdf组合能完成基础Markdown到PDF的转换，具备自动化批量处理的基础能力。

**发现问题与解决方案**：
1. **图片嵌入失败**
   - **现象**：PDF文件大小不包含图片体积，可能图片未加载
   - **原因**：wkhtmltopdf处理相对路径时无法正确解析文件位置
   - **解决方案**：使用绝对路径或Data URI方式嵌入图片

2. **CSS类未应用**
   - **现象**：pandoc生成的HTML没有应用自定义CSS类
   - **原因**：Markdown源文件使用纯Markdown语法，没有HTML class属性
   - **解决方案**：通过正则表达式或Pandoc过滤器进行Markdown预处理，为特殊元素添加HTML包装和CSS类

3. **字体依赖问题**
   - **现象**：指定专业字体（思源宋体、方正少儿简体）在系统中可能不存在
   - **解决方案**：研究字体嵌入或子集化方案，或使用可靠的后备字体链

**优化建议**：
- 开发Markdown预处理脚本，自动识别特殊元素（思想剧场、想一想、古人说、全球望远镜）并添加HTML包装
- 建立图片处理流程，确保插图正常嵌入PDF
- 制定字体管理方案，保障跨平台视觉一致性
- 扩展脚本支持12章批量处理，建立完整的排版流水线

### 图片管理系统优化（基于批量样张生成验证）
**发现问题与解决方案**：
1. **章节标题结构不匹配**
   - **现象**：批量生成时每章仅嵌入1张插图，未达到每章3-4张目标
   - **原因**：章节标题结构（如“第一营区”“第一课时”）与映射表中标准位置标签（“第一站”）不匹配
   - **解决方案**：实现灵活标题匹配函数，支持完全匹配、关键词匹配、数字站点变体匹配、通用前缀匹配；添加章节特定映射机制（第八章“after_second_station”）

**优化效果**：
- 匹配成功率：22个测试用例100%通过
- 图片嵌入完整性：11章全部达到预期数量（第2章4张、第3章2张、第4-11章各4张、第12章3张）
- 技术路径：保持Data URI嵌入，确保跨平台显示
- 文件体积：1.5MB-3.4MB（含图片数据）

## 6. 关键对齐要点（基于用户原始需求）
- **冯友兰精神**：采用“释古”态度，同情理解古人，不轻易评判；借鉴“子学时代”与“经学时代”框架，用“百家争鸣的星空”“思想融合的山谷”等意象包装。
- **中西视野**：在合适处用一两句话对比同时期古希腊或其他文明的思考（如“当庄子在说‘无用之用’时，古希腊的亚里士多德也在讨论‘幸福是什么’”）。
- **儿童经验锚点**：用孩子遇到的真实问题（分享、公平、害怕、输赢）对应古人智慧，让哲学变得“有用”。
- **避免简化主义**：不把哲学家贴成单一标签，展现他们思考的复杂性和自身矛盾。
