# 输出格式规范

## 报告格式说明

智能体生成的深度解析报告默认保存为 **Markdown格式**，用户可以直接打开阅读。

### Markdown格式（默认输出）
- **保存位置**：当前目录，文件名格式为 `{书名}-报告.md`
- **打开方式**：任何文本编辑器或Markdown编辑器
- **优势**：保留完整格式，便于查看和编辑

### 可选格式（按需生成）
如果用户需要，智能体可以调用导出工具生成以下格式：
- **PDF格式**：正式文档，便于打印或分享
- **Word格式**：可编辑文档，便于进一步编辑或添加内容

**注意**：如果Markdown文件中有图片引用（如 `![图片](assets/image.png)`），导出PDF和Word时可能无法正确处理图片。建议优先查看Markdown格式，或手动将图片插入到生成的PDF/Word文件中。

导出工具的内部实现细节见 [export-script-usage.md](export-script-usage.md)（内部文档）

```
# 《影响力》深度榨取报告

## 📚 书籍元信息
- 书名：《影响力：如何让人顺从》
- 作者：罗伯特·西奥迪尼
- 出版年份：2006
- 书籍类型判定：✅适合深度榨取
- 核心主题一句话概括：揭示影响人类决策行为的六大心理学原则
- 知识点总数：15个

## 🗺️ 内容地图
核心知识体系：
├── 互惠原则（Reciprocity）
│   ├── 经典案例：克利须那教派机场募捐
│   ├── 跨行业应用：电商试吃、教育培训免费资料、餐饮会员服务
│   └── 触发场景：需要影响他人决策时
├── 承诺与一致性（Commitment and Consistency）
│   ├── 经典案例：战俘改造实验、圣诞卡实验
│   ├── 跨行业应用：SaaS年度合约、健身房年卡、订阅服务自动续费
│   └── 触发场景：希望用户持续行为时
├── 社会认同（Social Proof）
│   ├── 经典案例：罐头笑声实验、多元无知效应
│   ├── 跨行业应用：电商销量展示、教育机构学员成功案例、餐厅排队营销
│   └── 触发场景：不确定如何决策时
└── ...（其他12个知识点）

## 📖 知识点深度解析
### 知识点 #1：互惠原则（Reciprocity）
**[通用层]** | 适用行业：全行业 | 关键词：销售、说服、人际关系、营销

#### 一句话定义
人们会本能地想要回报他人为自己所做的事情，哪怕这份"恩惠"是自己并未请求的。

#### 底层逻辑（Why）
互惠是人类社会协作的基础机制。进化心理学认为，能够"记住恩情并回报"的个体更容易在群体中生存，因此互惠本能被刻入了人类基因。这种本能如此强大，以至于即使是微小的、未经请求的善意，也会触发强烈的亏欠感和回报冲动。

#### 案例教学（How）
**[案例1-原书案例] 克利须那教派的机场募捐**
1970年代，克利须那教派成员在机场向路人赠送一朵花，然后请求捐款。数据显示，收到花的人捐款率比直接请求高出3倍以上。即使很多人并不想要那朵花（有人甚至转身扔掉），但"已经收了东西"的亏欠感仍然驱动他们掏出钱包。
**[解读]**：互惠的威力在于它绕过了理性判断——人们不是因为认同教派理念而捐款，而是因为"拿了人家的东西不好意思不给"。

**[案例2-跨行业·电商] Costco试吃策略**
Costco超市的试吃台是其标志性营销手段。数据显示，提供试吃的商品销量平均提升300%。关键细节：试吃员会与顾客进行眼神交流并微笑递上食物，这种"人际互动"而非"自助取用"的设计，强化了互惠心理——顾客会觉得"人家专门给我夹的，我不买点不好意思"。
**[解读]**：互惠效应的强度与"人情味"成正比。冷冰冰的自助试吃台效果远不如有真人服务的试吃台。

**[案例3-生活场景·职场沟通] 职场中的"先帮忙"策略**
你想请同事帮忙审核一份重要方案，但担心对方太忙会拒绝。高情商做法：提前一周主动帮对方做一件小事（如帮忙取快递、分享一份有用的资料），然后再提出请求。研究显示，这种"预存善意"的方式能将获得帮助的概率提升60%以上。
**[解读]**：互惠不仅是营销技巧，更是人际关系的润滑剂。但要注意：如果"帮忙"过于刻意或动机明显，反而会引发对方警觉。

#### 跨行业迁移矩阵
| 行业 | 互惠策略落地方式 | 执行要点 |
|------|------------------|----------|
| 电商 | 首单无门槛优惠券、包邮试用装 | 强调"免费送您"而非"促销活动" |
| 教育培训 | 免费公开课、干货资料包 | 内容必须有真实价值，不能是广告伪装 |
| 本地装修 | 免费量房+设计方案 | 方案要专业详细，让客户感受到诚意 |
| SaaS软件 | 14天全功能免费试用 | 试用期内提供人工客服支持，增加"人情债" |

#### 执行SOP
1. 识别目标客户的真实痛点或需求；
2. 设计一个"低成本但高感知价值"的前置善意（成本控制在获客成本的10%以内）；
3. 通过人际接触（而非冷冰冰的系统通知）传递这份善意；
4. 等待3-7天让互惠心理发酵，再提出你的请求或销售动作；
5. 请求时用"不知道您方不方便..."的软性话术，给对方台阶。

#### 触发场景
当你需要影响他人决策（销售、说服、请求帮助）时，先问自己："我能先为对方做点什么？"

#### 批判性视角
互惠原则的局限：(1) 如果"前置善意"被识别为"套路"，会引发心理抗拒（如保险推销员先送礼再推销的负面案例）；(2) 不同文化背景下互惠强度不同，东亚文化中互惠义务感更强；(3) 过度使用会导致"互惠疲劳"，长期客户对"免费"反而不敏感。

## 格式规范

### Markdown语法
- 使用标准Markdown语法
- 使用 `##` 和 `###` 标识层级
- 使用 `**粗体**` 标记关键词
- 使用 `|` 创建表格，用于"跨行业迁移矩阵"

### 分隔与标识
- 每个知识点之间用 `---` 分割线隔开
- 案例与案例之间用空行分隔
- 层级标签用方括号标注，如 `[通用层]`

### 案例格式
```
**[案例类型-行业/场景]** 案例标题
案例正文（80-150字，必须包含具体细节：人物、场景、对话、数据）
**[解读]** 解析内容（50-100字）
```

### 迁移矩阵格式
使用标准Markdown表格：

| 行业 | 落地方式 | 执行要点 |
|------|----------|----------|
| 电商 | 具体落地方式 | 关键执行要点 |
| 教育培训 | 具体落地方式 | 关键执行要点 |
| 餐饮 | 具体落地方式 | 关键执行要点 |

### 执行SOP格式
```
#### 执行SOP
1. [具体可执行的动作步骤]
2. [具体可执行的动作步骤]
3. [具体可执行的动作步骤]
```

### 费曼检验格式
```
## 🎯 费曼检验·情境模拟题 #N
**场景**：[具体场景描述，包含人物、环境、任务等]
**问题**：[基于场景提出的具体问题，而非抽象概念]
**参考答案要点**：
- 要点1
- 要点2
- 要点3
```

## 内容质量要求

### 案例描述
- 必须包含：人物、场景、对话/动作、数据/结果
- 禁止："比如可以用于..."、"例如在某些场景下..."
- 正确："某电商平台在双11期间，运营经理小李..."

### 底层逻辑解释
- 先给类比再给定义："就像...一样，XXX指的是..."
- 解释"为什么重要"和"生效边界在哪里"

### 批判性视角
- 中立客观，不贬低原书
- 补充边界条件和失效场景
- 提供"尽信书不如无书"的补充视角

## 输出完整性检查清单

- [ ] 书籍元信息完整
- [ ] 内容地图展示知识点关联
- [ ] 知识点数量在10-20个之间
- [ ] 每个知识点配齐2-3个案例
- [ ] 每个知识点包含跨行业迁移矩阵（至少3个行业）
- [ ] 每个知识点包含执行SOP（3-5步）
- [ ] 每个知识点包含批判性视角
- [ ] 每3-5个知识点后有费曼检验题
- [ ] 全书最后有批判性总结
- [ ] 格式规范，符合Markdown标准
- [ ] 无敷衍句式（"比如可以用于..."）
- [ ] 案例具体，有画面感

  - `cases`：案例数组，每个案例包含：
    - `title`：案例标题
    - `content`：案例内容
    - `interpretation`：案例解读
  - `migration_matrix_raw`：跨行业迁移矩阵（原始Markdown表格文本）
  - `sop`：执行SOP数组
  - `trigger`：触发场景
  - `critical`：批判性视角
- **quizzes**：费曼检验题数组，每题包含：
  - `id`：题目编号
  - `scenario`：场景描述
  - `question`：问题
  - `answer`：参考答案
- **summary**：全书总结对象

### 适用场景
- 集成到知识库（如RAG系统）
- 二次开发和数据处理
- API数据交互
- 数据分析和可视化

## Word格式

### 格式特点
- 可编辑文档，便于进一步编辑或添加内容
- 保留完整的报告结构和内容
- 适合与他人协作或进一步修改

### 使用方式
通过导出脚本生成：
```bash
python scripts/export_report.py book-report.md --format word
```

或批量导出：
```bash
python scripts/export_report.py book-report.md --format pdf,word
```

### 注意事项
- Word格式为简化版本，主要保留文本内容
- 表格、代码块等复杂格式可能需要手动调整
- 建议使用Microsoft Word、WPS Office或LibreOffice打开

---

## 格式选择建议

| 使用场景 | 推荐格式 | 原因 |
|---------|---------|------|
| 直接在对话中查看 | Markdown | 默认显示，清晰易读 |
| 保留原始格式 | Markdown | 完整保留Markdown语法 |
| 打印或分享 | PDF | 格式固定，跨平台一致 |
| 进一步编辑 | Word | 可编辑，便于协作 |
| 同时需要多种用途 | 批量导出 | 一次生成多种格式 |

## 输出流程

1. **生成Markdown报告**：智能体在对话中生成完整报告并保存为Markdown文件
2. **预览报告**：在对话中显示报告预览供用户查看
3. **选择导出格式**：根据需求导出为PDF或Word格式
4. **使用输出**：根据格式特性进行后续操作（打印、编辑、分享等）
